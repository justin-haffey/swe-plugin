# Bounded delivery orchestration

Follow the [delivery contract](../../../references/ARTIFACT-CONTRACT.md). Keep one coordinator per checkout, named writer scopes, prerequisite state, current decisions and pending checks. Do not write mandatory per-agent manifests, duplicated requirements or review packets.

Standalone: Feature/approach -> implementation + Evidence -> independent Validation. Architecture is reused or changed when needed. One qualified developer may own the complete bounded implementation; package/module levels do not require nested agents. Optional Epic groups local Features.

Portfolio: shared Feature + allocation -> eligible child Design/implementation -> local Validation -> integration acceptance. Read real participating checkout identities, shared contract and dependency edges. An unrelated waiting Plan is not a global barrier. Design may proceed on approved interfaces; consuming behavior requires accepted evidence for that exact generation. Bridge only cross-repository work through authorized transport; same-repository assignments use ordinary local delegation.

A contribution message carries owned scope/paths, direct input locators, procedure, expected output and recipient. Tell writers they are not alone and preserve concurrent changes. Keep reviewer independence from author/designer/material repairer. Never make a tester judge adequacy or repair tests.

Reuse sessions for related developer work; use independent reviewer contexts. Reuse applicable current receipts; request only missing/stale or independently necessary tests. Serialize shared build outputs or prove isolation. Test the actual child checkout with one fixture set, no code snapshots or copied corpora.

Human-default decisions, explicit auto-approval policy, named Major human decisions, frozen review bytes and maximum two repair cycles apply across resume and successor records. Keep history in the existing artifact/review record. A return message/handle is not evidence.

Persist a small derived recovery view only on actual interruption need: artifact/receipt locators, pending obligations, live handles and next action. Recheck changed bytes and live handles on resume; never invent active work from an old status. Recovery cannot approve or reset a review counter.
