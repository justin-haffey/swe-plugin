# Delivery completion

The primary coordinator alone updates the matching host Goal. Follow host completion, pause and repeated-blocker rules; no child may create or modify a Goal. A budget limit is not success.

Before completion verify against current files and receipts:
- Every requested Feature/assignment implemented within approved scope; no missing or silently omitted work.
- Required current checks passed; no pending, stale, failed or unavailable evidence accepted as success.
- Independent local acceptance, actual reviewer identity and preserved review-cycle history; accepted requirements alone do not prove delivery.
- Portfolio only: every allocated criterion covered and shared integration accepted by its owner; all participating child returns are verified.
- Applicable architecture reconciled; operational claims backed by operational evidence.
- Requested documentation/deliverables exist. No unauthorized external deployment/publication/Git action.

Implementation complete, Verification complete and Delivery accepted are distinct. A standalone Feature needs no portfolio or Epic decision. An optional Epic aggregates its Features. Material findings need governed resolution; a universal additional SWA report is not required.

Report canonical records, bounded check results and residual risks. If required evidence is missing, continue authorized work or report the exact blocker without marking the Goal complete.
