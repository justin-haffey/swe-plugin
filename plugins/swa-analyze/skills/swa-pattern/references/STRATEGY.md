# Pattern-Language Analysis

## Core question

Turn repeated architectural structures into an explicit, evidence-backed pattern language and replace unfit repetition with better forms.

## Analyze

- Locate recurring responsibility, dependency, state, workflow, integration, and failure-handling structures across the bounded scope.
- Separate intentional patterns from coincidental similarity and copied implementation.
- Evaluate each pattern against the outcomes, qualities, and contexts in which it succeeds or fails.
- Name the forces, context, solution shape, consequences, and contraindications for useful patterns.
- Propose adapted or newly invented patterns only where they reduce demonstrated inconsistency or structural cost.

## Recommendation test

A strong recommendation describes a reusable decision rule with context and consequences, shows multiple supporting instances, and avoids forcing unlike cases into one abstraction.

## Avoid

Do not import fashionable catalog patterns without evidence, confuse clone detection with architectural recurrence, or refactor during analysis.
