The existing Ghostworx governance and accepted work remain intact; adoption requires a reviewed change at an explicit work boundary.

## Deliverables and execution order

1. Establish one V4 delivery contract: standalone and federated solution ownership; three ordinary records; one fast-path record; conditional portfolio planning; small headers; unchanged human defaults and independent acceptance.
2. Align delivery/planning/coordinator skills and agent roles. Centralize models in native roles, eliminate repeated ancestor reconstruction, retire Prototype Mode, and limit orchestration to actual ownership/dependency needs.
3. Update generators/readers and templates together. Keep legacy readers and receipts; support compact direct locators and combined Feature/approach without phantom Plan/Design requirements.
4. Refresh canonical scaffolds and the additive copier last. Provide explicit standalone versus federated mode and preserve customized destinations.
5. Set all four plugin manifests/display names/catalog to 4.0.0. Publish repository-local QUICKSTART.md with executable scaffold commands and realistic prompts for one solution and related solution delivery.
6. Route required validation through the native test-runner. Exercise standalone capability creation, federated allocation, single-record fast paths, compact/legacy artifacts, no-clobber copying, and existing receipt/approval protections. Record results without claiming live application delivery.
